Where business logic lives in a system generated by modux. A custom operation is declared in the model with its intent in plain words; generation turns it into a hook — an interface in the generated code — and scaffolds a default implementation, once, in a module of its own. The rule is written there, in plain Java. Change the model and generate again: the generated code follows, the custom module is never touched. Edit a generated file by hand and the next generation reports it and puts the generated version back. Then the rule, running: a book withdrawn, and refused the second time.

Everything on screen is real: the model files, the output of each mvn modux command, the generated and the hand-written code, and the generated application running. The example is the library from episode 2.
